# What scrcpy and ADB could add to Rebroid

Research date: 21 November 2026. Rebroid bundles scrcpy **5.0.1** and runs its Android server with a custom browser client. A feature in the desktop client can establish the interaction design, while the server source tells us which pieces Rebroid can reuse. The sidecar installs the distribution's ADB package, so device-side commands and output still need checking on the supported ReDroid 13–16 images. These are source-based proposals. Effort and UX impact are estimates. [Sidecar Dockerfile](../../apps/display-sidecar/Dockerfile) · [Server launch options](../../apps/display-sidecar/src/modules/scrcpy/scrcpy.service.ts) · [Rebroid display support matrix](../display-streaming.md#manual-verification) · [Upstream release](https://github.com/Genymobile/scrcpy/releases/tag/v5.0.1)

**I would ship wheel scrolling first, then a searchable package launcher and file drop onto the viewer.** They cover three ordinary tasks: reading a long screen, opening an installed app, and supplying a file to it. Each can be evaluated with one user journey. For teams building workflows, the element picker below is the strongest next investment.

## What to validate first

- **Desktop interaction.** On each transport, scroll a long list, open an installed app, and supply a file while its picker is open. Check for accidental page scroll, wrong-display input, and file-picker refresh behavior.
- **Workflow authoring.** Ask an operator to build one wait step from a visible label. Check that the resulting draft works after a layout change and that duplicate labels prompt a choice.
- **Host-dependent features.** Exercise secondary-display launch, keyboard placement, and resizing across the supported images. Use a real ReDroid host for any change touching scrcpy startup or socket ordering. [Manual verification matrix](../display-streaming.md#manual-verification)

Screen recording would need a separate bounded-storage and lifecycle design under current repository rules. Hardware-dependent features such as gamepad forwarding would first need a representative deployment with Android UHID support and a user case that justifies adding another browser input path.

# Domain docs

Rebroid uses a single domain context. Keep the glossary in `GLOSSARY.md` at the repository root and architecture decision records (ADRs) in `docs/adr/`.

- Before exploring the codebase, read the glossary and the ADRs that cover the area you are working in. Proceed with the files that exist.
- Use glossary terms in issues, proposals, and tests. If a term is missing, check existing project usage and capture the gap when doing domain modeling.
- When a proposal would reopen an existing ADR, cite the ADR and explain why the decision merits reconsideration.
- Create the glossary when the first term is agreed. Add an ADR when an architectural decision is ready to record.
